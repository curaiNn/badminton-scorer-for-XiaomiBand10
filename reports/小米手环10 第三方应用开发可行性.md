# 绕开官方门槛，把计分器装进手环10

**能做，也能装上、用起来，只是装机要走社区通道，官方通道对个人不开放。** 小米手环10 运行 Xiaomi Vela 系统，小米官方的"Xiaomi Vela JS 应用"框架（安装包为 .rpk，社区俗称快应用）在设备表和各接口的支持明细里逐项点名"小米手环 10"。你的计分器需要的点击与长按、短/长两档振动、本地存储、页面跳转和屏幕常亮都有现成接口，手环10 不支持的网络、蓝牙等能力这个应用一项都用不到。在 Mac 上，小米提供原生 Apple Silicon 版 AIoT-IDE、能装进普通 VS Code 的官方扩展和纯命令行工具 aiot-toolkit，模拟器也有原生 arm64 版本；但模拟器没有手环10 专用镜像，颜色、字形、触控和息屏行为都得上真机确认。真正的门槛在安装：官方真机调试只支持合作方的 Xiaomi Watch S4，小米运动健康里的第三方应用安装页只存在于商务渠道发放的测试版，上架应用商店要走"合作发布"，个人开发者三条路都走不通。可行的主路是米坛社区的免费工具 AstroBox，它把"小米手环 10 系列"列为完整支持，Mac、iPhone、安卓都有版本，通过蓝牙直接安装本地 .rpk，而且不用把手环从小米运动健康解绑；安卓用户另有表盘自定义工具、BandBurg 等备选。代价是要把小米账号或设备 AuthKey 交给第三方工具、每次安装都要在两个应用之间切换蓝牙连接，并承担小米日后收紧固件或工具政策的风险；安装 .rpk 不刷写固件，硬件风险很低。应用设计上最大的坑是息屏后应用会被挂起甚至关闭，所以每得一分都要存盘、比赛中要保持常亮，而胶囊屏的圆端意味着"右上角"按钮必须往里收。社区已有至少五款手环羽毛球计分器证明整条链路走得通，但没有一款同时提供 21/15 分制可选、每分持久化和开放许可，你的应用有它的位置。

## 手环10 在官方支持名单内，五款羽毛球计分器已先行跑通

小米手环10 运行的是基于 NuttX 的 Xiaomi Vela 系统。小米官方对"Xiaomi Vela JS 应用"的定义是基于 Vela OS 开发的一类应用：用 JavaScript 按 MVVM、声明式 UI 的方式编写，项目由 manifest.json、.ux 页面文件、CSS/JS 和资源组成，最后打包成可安装的 .rpk ([Vela JS 概述](https://iot.mi.com/vela/quickapp/zh/guide/index.html))。官方"多屏适配"设备表中有一行明确写着 **小米手环10：胶囊形、1.725 英寸、212×520、326 PPI、宽 106 dp** ([多屏适配](https://iot.mi.com/vela/quickapp/zh/guide/multi-screens/index.html))，振动、事件等接口页面的"支持明细"表也逐一把小米手环 10 列为支持设备 ([事件 event](https://iot.mi.com/vela/quickapp/zh/features/system/event.html))。社区拆解固件的结果与此一致：手环10 固件（代号 o66）的 OTA 包里有一个独立的 quickapp 分区，装好的 rpk 放在 `/data/app/<包名>/` 下 ([dargon682 模拟器笔记](https://github.com/dargon682/xiaomi-band10-vela-emulator))。在手环产品线上，快应用支持从 2023 年 8 月的小米手环8 Pro 开始，之后的手环9、9 Pro、10 都带有快应用引擎 ([路明笔记](https://www.luming.cool/posts/2025/08/build-a-quick-app-for-vela-devices/))。

你手上这套"NFC 版、国行、绑定小米运动健康"，正是证据最充分的组合。小米香港官方 FAQ 列出的 NFC 版与标准版差异只有 NFC 芯片和表扣材质两处 ([Mi HK 手环10 FAQ](https://www.mi.com/hk/support/faq/details/KA-580855/))，没有任何来源提到两者在应用平台上有区别，社区统计的差别只在存储空间，NFC 版可用约 323 MB ([米坛知识库](https://www.bandbbs.cn/threads/22175/))。唯一的地区争议出在手环10 **Pro** 上：有开发者发现它的国际版固件 3.201.016 不响应第三方应用服务，国行固件 3.101.042 则正常，同一讨论里也有人反驳说国际版用 AstroBox 照样能装 ([atc1441 issue #3](https://github.com/atc1441/MiBand10-BES2700iMP-BEST1503-Hacking/issues/3))。这件事与你的国行标准款无关。

更直接的可行性证据，是已经跑在手环上的同类应用。米坛社区上，免费的"小米手环10-羽记"（2026-03 发布，283 次下载）用上下滑动加分、左滑撤销，支持单双打站位 ([bandbbs #5807](https://www.bandbbs.cn/resources/5807/))；售价 1 元的"羽球助手"在计分板之外加入了击球计数和球速估算 ([bandbbs #6912](https://www.bandbbs.cn/resources/6912/))。GitHub 上，zhangchi1997/badminton_scoring 面向手环10 与 10 Pro，单击加分、双击减分、比赛中常亮，但只有单局 21 分，也不保存比分 ([zhangchi1997/badminton_scoring](https://github.com/zhangchi1997/badminton_scoring))；j-iNFINITE/Badminton_score_app 实现了三局两胜、发球区和换边提示，却只适配 336×480 的手环9 Pro ([j-iNFINITE/Badminton_score_app](https://github.com/j-iNFINITE/Badminton_score_app))；Godminton 则把手环10 计分器和安卓端的 Flutter 计分板联动起来 ([Godminton](https://github.com/jinergenkai/badminton-system))。AstroBox 官方资源库收录的 191 个快应用里，一个计分器都没有 ([AstroBox-Repo](https://github.com/AstralSightStudios/AstroBox-Repo))。

这几个开源项目都没有许可证文件（j-iNFINITE 只在 README 里写了 MIT），只适合参考思路，不宜复制代码。可以放心借用代码的是板网球计分器 **miSmash**：它采用 MIT 许可，作者注明在手环10 上实测过，它的单页状态机、每分即存、比赛中常亮和长按撤销，几乎就是你这个应用的骨架 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))。对照下来，**现有羽毛球计分器里没有一款同时做到 21/15 分制可选、每分持久化和开放许可**，你不是在重复造轮子。

## 每项需求都能落到手环10 已开放的接口上

### 逐项对照：振动、按钮位置和应用名需要变通

下表把你列出的需求逐项对应到 Vela JS 的组件与接口，并标出手环10 的支持状态和最容易踩的坑。

| 需求 | 实现方式 | 手环10 支持情况 | 关键注意点 |
|---|---|---|---|
| 红蓝两方、无需队名 | 上下两个色块 `div`，各放一个大号 `text` 显示比分 | 通用组件，可用 | 根节点上的全屏背景色在真机上会显示成黑色，红蓝色要写在内层定高容器的静态 class 上 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))；不支持渐变 ([band-metronome](https://github.com/q879604/band-metronome)) |
| 全程点击、不输入文字 | `onclick`、`onlongpress` | 可用 | 框架本来就没有文本框，`input` 只有 button、checkbox、radio 三种 ([input](https://iot.mi.com/vela/quickapp/zh/components/form/input.html)) |
| 点一方区域加 1 分 | 色块上的 `click` | 可用 | 用 flex 布局加原生 onclick，不要绝对定位按钮，也不要自己算触点坐标 ([band-metronome](https://github.com/q879604/band-metronome)) |
| 减分 | 长按该方色块减 1，或单独放一个"撤销"按钮 | `longpress` 可用，没有双击事件 ([通用事件](https://iot.mi.com/vela/quickapp/zh/components/general/events.html)) | 长按松手后可能紧跟一次 click，要把它吞掉 ([pickleball game.ux](https://github.com/mahmoodw/pickleball-band/blob/HEAD/band/src/pages/game/game.ux)) |
| 当前比分与局分 | 大号粗体 `text`；局分放在顶栏 | `font-weight` 只有 normal 和 bold 两种 ([text](https://iot.mi.com/vela/quickapp/zh/components/basic/text.html)) | 文本盒高度低于约 1.33 倍字号时，数字会被裁切 ([miband-dev 校准数据](https://github.com/sohamashodiya/miband-dev/blob/main/plugins/miband-dev/data/profiles/band11/profile.json)) |
| 重置本局、快速开新比赛 | 设置页按钮，加一个自绘的确认层 | 可用 | `showToast` 只能显示在屏幕正中，会盖住比分 ([Godminton UI 笔记](https://github.com/jinergenkai/badminton-system/blob/main/watch/docs/watch-ui-gotchas.md))；`showDialog` 不在官方文档里 ([prompt](https://iot.mi.com/vela/quickapp/zh/features/other/prompt.html)) |
| 21 分 / 15 分制 | 用 `@system.storage` 保存设置 | 可用 | 读写都是异步回调 ([storage](https://iot.mi.com/vela/quickapp/zh/features/data/storage.html)) |
| 振动反馈 | `vibrator.vibrate({mode: 'short'})` 或 `'long'` | `vibrate` 可用；`start`、`stop`、`getSystemDefaultMode` 不可用 ([vibrator](https://iot.mi.com/vela/quickapp/zh/features/system/vibrator.html)) | 只有短、长两档，不能调强度或时长 |
| 右上角"更多功能"进入设置页 | `router.push` 进入，`router.back` 或系统右滑返回 | 可用 ([router](https://iot.mi.com/vela/quickapp/zh/features/basic/router.html)) | 右上角落在胶囊圆端里，按钮要往里收、往下移，而且不能放在红方色块内部 |
| 比赛中不熄屏（隐含需求） | `brightness.setKeepScreenOn` | 官方页面没有设备支持表，但已有多款手环10 应用在用 ([brightness](https://iot.mi.com/vela/quickapp/zh/features/system/brightness.html)) | 离开计分页时要关掉，否则一直耗电 |

**振动**是受限最明显的一项。官方支持明细把 `vibrate` 标为手环10 可用，但能设定时长、间隔、次数的 `start`/`stop`，以及读取系统振动强度的 `getSystemDefaultMode`，只有 Xiaomi Watch S5 支持 ([振动 vibrator](https://iot.mi.com/vela/quickapp/zh/features/system/vibrator.html))；有社区应用给 `vibrate` 传了 `duration` 参数，这并不是文档定义的用法 ([j-iNFINITE](https://github.com/j-iNFINITE/Badminton_score_app))。所以振动反馈只有两种：普通得分用短震，局终、换边、比赛结束用长震，如果还需要第三种信号，只能用 setTimeout 连发两次短震。**存储**方面，`storage` 是异步的字符串键值存储，`get` 在键不存在时返回 default 或空串，把值设为空串就等于删除这个键 ([数据存储 storage](https://iot.mi.com/vela/quickapp/zh/features/data/storage.html))。手环10 上的匹克球计分器把整场比赛序列化成 JSON 存在一个键下，并保留最多 100 步撤销历史 ([pickleball-band](https://github.com/mahmoodw/pickleball-band))，这个做法可以直接照搬。

**事件**方面要注意冒泡：除 swipe 外，触摸和点击事件都会冒泡到父节点 ([通用事件](https://iot.mi.com/vela/quickapp/zh/components/general/events.html))。如果把"更多"按钮放在红方色块内部，点它会顺带给红方加一分，所以按钮必须放在一个与红蓝色块平级的独立顶栏里。双击减分要像 zhangchi1997 那样自己用 200 ms 的时间窗口判断 ([zhangchi1997](https://github.com/zhangchi1997/badminton_scoring))，代价是每次加分都要等 200 ms 才能确认，因此长按减分或单独的撤销按钮更合适。

项目配置上有三处必须改。第一，manifest 的 `name` 字段官方限定"6 个汉字以内" ([项目配置 manifest](https://iot.mi.com/vela/quickapp/zh/guide/framework/manifest.html))，**"羽毛球比赛计数器"有 8 个字，超出了限制**，桌面名可以用"羽球计分"这类短名，完整名字放到应用内的标题里。同一页还规定图标为 192×192、`versionCode` 是每次上传都要递增的整数，绝大部分接口必须在 `features` 中声明才能调用。漏声明的后果，社区说法不一：有人遇到编译直接失败 ([hermes 指南](https://github.com/paraflu/hermes-skill-xiaomi-miband10-vela-js/blob/HEAD/references/development-pitfalls-and-tips.md))，有人遇到编译通过、运行时崩溃 ([Godminton UI 笔记](https://github.com/jinergenkai/badminton-system/blob/main/watch/docs/watch-ui-gotchas.md))，miSmash 还发现文档写着无需声明的 `@system.app` 实际上也要声明 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))。

第二，CSS 里的 `px` 不是物理像素，而是按 `designWidth` 缩放的类 rem 单位，不填时默认按 480 计算 ([页面样式与布局](https://iot.mi.com/vela/quickapp/zh/guide/framework/style/page-style-and-layout.html))，在 212 像素宽的手环10 上，所有尺寸都会被悄悄缩到约 44%。手环10 项目普遍设为 `designWidth: 212`，让 1 px 正好等于 1 个物理像素 ([pickleball manifest](https://github.com/mahmoodw/pickleball-band/blob/HEAD/band/src/manifest.json))。第三，目前能在手环10 上运行的项目，`minPlatformVersion` 有 1000、1100、1200 三种写法，官方脚手架默认 1200 ([vela-demo manifest](https://cdn.jsdelivr.net/npm/create-aiot@2.0.5/lib/template/ux/vela-demo/src/manifest.json))；`deviceTypeList` 保持 `["watch"]` 不动，有社区指南称改成 `"band"` 能编译但装机会失败 ([hermes 指南](https://github.com/paraflu/hermes-skill-xiaomi-miband10-vela-js/blob/HEAD/references/development-pitfalls-and-tips.md))。

样式上还有几条限制。框架只支持 flex 布局，选择器只有 class、id、标签三种，没有 `:active` 之类的伪类，按下效果只能靠动态切换 class；`border-radius` 必须同时设置 border-width 和 border-color 才生效 ([通用样式](https://iot.mi.com/vela/quickapp/zh/components/general/style.html)；[style 样式](https://iot.mi.com/vela/quickapp/zh/guide/framework/style/index.html))。`text` 的默认颜色是 `rgba(0, 0, 0, 0.54)`，在黑色 AMOLED 屏上几乎看不见，每段文字都要明确写上颜色 ([text](https://iot.mi.com/vela/quickapp/zh/components/basic/text.html))。官方还明确不建议在手表、手环上使用自定义组件，因为每个自定义组件都有独立的 ViewModel，会额外占内存 ([自定义组件](https://iot.mi.com/vela/quickapp/zh/guide/framework/template/component.html))。

### 21 分制与 15 分制只差一组参数

15 分制不只是一个可选项，它马上就是正式规则。世界羽联会员在 2026 年 4 月 25 日的第 87 届年度大会上以三分之二多数通过了 3×15 赛制，**自 2027 年 1 月 4 日起取代 3×21** ([Bernama](https://bernama.com/en/news.php?id=2549450)；[USA Badminton](https://usabadminton.org/bwf-approves-3x15-scoring-system/))，3×21 保留为双方事先约定即可采用的替代规则 ([BWF 替代规则](https://ghanabadminton.org/wp-content/uploads/Section-4.1.4-Alternative-Laws-of-Badminton-04-January-2027-V2.0.pdf))。两种赛制都是每球得分、三局两胜，差别只在下表这几个数字，3×15 的数字出自 [BWF 3×15 规则](https://www.cba.hr/storage/reports/U-svibnju-zapoinje-novi-testni-sustav-bodovanja-20250404071756/files/3%20x%2015%20Scoring%20System%20Test%20-%20Laws%20-%20April%202025%20-%20MA%20Update.pdf)，3×21 的数字出自 [BWF 替代规则](https://ghanabadminton.org/wp-content/uploads/Section-4.1.4-Alternative-Laws-of-Badminton-04-January-2027-V2.0.pdf)。

| 赛制 | 每局目标分 | 追平后须领先 2 分 | 封顶 | 决胜局换边 |
|---|---|---|---|---|
| 3×15 | 15 | 14 平起 | 20 平时先得第 21 分者胜 | 一方先到 8 分 |
| 3×21 | 21 | 20 平起 | 29 平时先得第 30 分者胜 | 一方先到 11 分 |

所以只要一个以（目标分、追平线、封顶分、决胜局换边分）为参数的规则引擎，就能同时覆盖两种赛制：3×21 取（21, 20, 30, 11），3×15 取（15, 14, 21, 8）。局胜方下一局先发球、单打按发球方得分的奇偶决定左右发球区，这些规则在两种赛制里都一样 ([Wikipedia: Badminton](https://en.wikipedia.org/wiki/Badminton))，以后想加发球区提示也不用改引擎。前面列出的手环羽毛球计分器，介绍里都没写明支持 15 分制，这正是你的应用的差异点。

### 胶囊屏、息屏挂起和系统右滑是三条硬约束

**第一条约束是屏幕形状。** 手环10 的屏幕是 1.72 英寸、212×520 的胶囊形 AMOLED，峰值亮度 1500 尼特，振动来自线性马达 ([小米手环10 规格](https://www.mi.com/global/product/xiaomi-smart-band-10/specs/))。胶囊两端是大半圆：社区在使用同一块 212×520 面板的手环11 上实测圆端半径约 103 px ([miband-dev 校准报告](https://github.com/sohamashodiya/miband-dev/blob/main/plugins/miband-dev/data/profiles/band11/CALIBRATION.md))，miSmash 按约 90 px 的半径在上方留 40 px、下方留 24 px 边距 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))，Godminton 的真机经验是四个角不放按钮、顶部留约 30 px ([Godminton UI 笔记](https://github.com/jinergenkai/badminton-system/blob/main/watch/docs/watch-ui-gotchas.md))，小米自己的设计规范也要求把主要功能放在圆端以外的安全区里 ([多屏设计](https://iot.mi.com/vela/quickapp/zh/guide/design/multi-screens.html))。这直接影响"右上角放'更多功能'按钮"的设想：字面意义上的右上角正好在圆弧里，按钮会被切掉一角，也很难点中。可行的布局是把顶部圆端做成一条不参与计分的状态栏，左边显示局分，右边放"更多"按钮，按钮距上沿约 30–40 px 并向内收；由于 `stack` 里绝对定位元素的 `right` 属性会被忽略 ([Godminton UI 笔记](https://github.com/jinergenkai/badminton-system/blob/main/watch/docs/watch-ui-gotchas.md))，右对齐要用 flex 的 `justify-content` 实现。

比分数字同样有讲究。手环11 的校准数据表明，文字行盒高 1.33 em，盒子比行盒矮时数字会贴着顶部显示并被裁切，而且粗体数字宽度随字符而变，"1111"明显比"0000"窄 ([miband-dev 校准数据](https://github.com/sohamashodiya/miband-dev/blob/main/plugins/miband-dev/data/profiles/band11/profile.json))；miSmash 在手环10 上用的"96 px 粗体、110 px 行高"可以直接作为起点 ([miSmash index.ux](https://github.com/loStefa/miSmash/blob/main/src/pages/index/index.ux))。粗体会不会发虚存在分歧，QRWallet 主张不用粗体，miSmash 实测粗体正常 ([QRWallet](https://github.com/mastermaiolo/QRWallet))，需要在真机上对比。emoji 在手环上会显示成方框 ([Senren-Banka](https://github.com/hrk666666/Senren-Banka-MiBand-10))，所以"更多"按钮应该用文字或 PNG 图标。

**第二条约束是生命周期。** 官方规定应用切到后台就停止运行，只有声明了音频、网络请求或定位等后台能力的应用例外 ([后台运行](https://iot.mi.com/vela/quickapp/zh/guide/framework/other/background-running.html))，而网络请求和定位在手环10 上本来就不支持 ([fetch](https://iot.mi.com/vela/quickapp/zh/features/network/fetch.html))；官方还提示，息屏后重新亮屏会再次触发 onShow ([注意事项](https://iot.mi.com/vela/quickapp/zh/guide/other/tips.html))。社区在手环9 Pro 上观察到息屏后 JS 计时器会被挂起 ([band-metronome](https://github.com/q879604/band-metronome))，miSmash 的作者在代码注释里直接写着"手环可能随时关闭应用" ([miSmash index.ux](https://github.com/loStefa/miSmash/blob/main/src/pages/index/index.ux))。手环10 上的第三方应用息屏后再亮屏，到底回到应用还是回到表盘，目前既没有文档也没有实测。

稳妥的做法分两部分。一是存盘：每得一分，就把完整比赛状态（比分、局分、赛制、撤销栈）写进 storage，在 onInit 和 onShow 中恢复，并保证 onShow 重复执行也不出错。二是常亮：计分页在 onShow 里调用 `setKeepScreenOn({keepScreenOn: true})`，在 onHide 和 onDestroy 里关掉。这个接口在官方亮度文档里有，但没有设备支持表 ([屏幕亮度 brightness](https://iot.mi.com/vela/quickapp/zh/features/system/brightness.html))；手环10 上的单词应用、miSmash 和 zhangchi1997 都在用它，zhangchi1997 还会在空闲 3 秒后把亮度降到 30/255、触摸或抬腕时再恢复，以压低常亮耗电 ([zhangchi1997](https://github.com/zhangchi1997/badminton_scoring))。如果这个接口在你的手环上不生效，退路是系统设置：待机时间最长能调到 5 分钟，"持续亮屏"最长 20 分钟，但官方提示后者会显著增加功耗 ([Mi HK 手环10 FAQ](https://www.mi.com/hk/support/faq/details/KA-580855/))。

**第三条约束是系统手势。** 在手环10 主屏以外的任何页面，从左边缘向右滑都是"返回上一屏" ([Mi HK 手环10 FAQ](https://www.mi.com/hk/support/faq/details/KA-580855/))，这个手势会触发页面的 onBackPress，返回 true 就能拦截下来自己处理 ([生命周期](https://iot.mi.com/vela/quickapp/zh/guide/framework/script/lifecycle.html))。计分页应该拦截它，比如提示"再滑一次退出"，以免挥拍时误触退出；整个应用也不宜使用水平滑动手势。这样看来，"全程点击"的交互在手环上恰好最稳。

最后还有两点需要上真机确认。一是手环原生运动记录进行中时，第三方应用可能打不开，这一说法只有单一来源 ([pickleball-band](https://github.com/mahmoodw/pickleball-band))，也就是说你也许没法一边开着手环自带的羽毛球运动记录、一边用自己的计分器。二是资源上限：官方没有公布 rpk 大小、JS 内存或页面数量的上限，只要求首页渲染不超过 2000 ms、尽量减少页面数量 ([验收标准](https://iot.mi.com/vela/quickapp/zh/guide/publish/acceptance-criteria.html)；[内存优化](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/memory.html))。一个只有计分页和设置页、代码只有几 KB 的计分器，离任何已知的出问题规模都很远；社区里真正让手环10 重启的，是一个内置 6000 词词库的单词应用 ([Bingak 单词应用](https://github.com/Bingak/MiBand10-Daily-Word-Practice))。

## Mac 能独立完成编码、模拟器预览和打包，但没有手环10 专用镜像

你在 Mac 上有三种开发入口，能力上没有区别。第一种是官方独立 IDE **AIoT-IDE 1.7.0**，它基于 VS Code，下载页为 Apple Silicon 和 Intel 分别提供原生安装包，要求 macOS 14 及以上；如果系统提示"已损坏，无法打开"，官方的解决办法是用 `sudo xattr -r -d com.apple.quarantine` 去掉隔离属性 ([使用 AIoT-IDE 开发](https://iot.mi.com/vela/quickapp/zh/guide/start/use-ide.html))。第二种是在**普通 VS Code 中安装官方扩展 `vela.aiot-core`**（会连带装上 `vela.aiot-emulator`）：扩展从 1.7.19 版（2026-05-28）起正式支持 VS Code 及基于它的编辑器，最新的 1.7.22 发布于 2026-07-21 ([aiot-core 更新日志](https://vela.gallerycdn.vsassets.io/extensions/vela/aiot-core/1.7.22/1784640272242/Microsoft.VisualStudio.Services.Content.Changelog))，要求 VS Code 1.99 以上 ([Marketplace: aiot-core](https://marketplace.visualstudio.com/items?itemName=vela.aiot-core))，工具栏位于左侧边栏的 vela 图标下 ([aiot-core 说明](https://vela.gallerycdn.vsassets.io/extensions/vela/aiot-core/1.7.22/1784640272242/Microsoft.VisualStudio.Services.Content.Details))。独立 IDE 停在了 2025 年 6 月，扩展却一直在更新，所以这条路的版本更新。第三种是**纯命令行**：IDE 背后的构建引擎是 aiot-toolkit，最新稳定版为 2.0.5，官方说明它"提供了脱离 AIoT-IDE，独立开发 Xiaomi Vela JS 应用的能力" ([AIoT-toolkit](https://iot.mi.com/vela/quickapp/zh/tools/toolkit/start.html))，FAQ 也确认 Mac 能打包 rpk ([常见问题](https://iot.mi.com/vela/quickapp/zh/guide/other/faq.html))，它的命令行在 Node.js 低于 18 时会直接退出 ([aiot-toolkit bin.js](https://cdn.jsdelivr.net/npm/aiot-toolkit@2.0.5/lib/bin.js))。官方文档里没有任何登录或账号步骤，工具包都公开发布在 npm 上 ([npm: aiot-toolkit](https://www.npmjs.com/package/aiot-toolkit))。

**这台 Mac 的条件基本就绪。** 本机检测（2026-10-21）显示它是 Apple Silicon（arm64）、macOS 26.5.1，已装 VS Code 1.137 和通过 nvm 安装的 Node 22.21.1，满足上面所有的版本要求。有两件事要留意。第一，到目前为止，没有任何来源报告过 Vela 工具链在 macOS 26 或 Apple Silicon 上的实际运行情况，说它原生支持，依据只是 CDN 上的安装包和工具源码。第二，在本次检测用的 shell 里，`npm` 指向的是 Homebrew 目录下的 8.1.0 版，而不是 nvm 里 Node 22 自带的 10.9.4 版，开工前应先让 `which npm` 指向 `~/.nvm`。另有一条说法称 Node 20 以上可能导致构建失败，但它未经证实且与其他指南矛盾 ([CSDN 安装教程](https://blog.csdn.net/Krisotopher/article/details/147383410))；如果遇到莫名其妙的构建错误，可以用 nvm 切换到 Node 18 或 20 排查。

**命令行流程从 `npm create aiot` 开始。** 脚手架只带 `ux/vela-demo` 和 `ux/android-demo` 两个模板 ([create-aiot 模板列表](https://cdn.jsdelivr.net/npm/create-aiot@2.0.5/lib/template/template.json))。vela-demo 是一个手表示例，包名 `com.application.watch.demo`，`designWidth` 为 480，`minPlatformVersion` 为 1200 ([vela-demo manifest](https://cdn.jsdelivr.net/npm/create-aiot@2.0.5/lib/template/ux/vela-demo/src/manifest.json))，需要按上一节改成手环10 的配置；IDE"新建项目"里的 8 个模板也都不是手环专用的 ([新建项目](https://iot.mi.com/vela/quickapp/zh/tools/project/creat-project.html))。aiot-toolkit 2.0.5 实际提供的命令有 `build`、`release`、`start`、`initEmulatorEnv`、`createVVD`、`deleteVVD` 和 `resign`，官方文档里写的 `crateVelaAvd` 是过时或拼错的命令名 ([aiot-toolkit bin.js](https://cdn.jsdelivr.net/npm/aiot-toolkit@2.0.5/lib/bin.js)；[AIoT-toolkit](https://iot.mi.com/vela/quickapp/zh/tools/toolkit/start.html))。`aiot start --watch` 会依次检查模拟器 SDK、创建模拟器、编译、启动模拟器、安装并运行 rpk，之后每改一次文件就自动热更新 ([VelaUxStarter.js](https://cdn.jsdelivr.net/npm/aiot-toolkit@2.0.5/lib/starter/VelaUxStarter.js))。

**模拟器基于 QEMU，由工具链按需从小米北京的 CDN 下载。** macOS 原生 arm64 版确实存在，有 v0.1.0（2024-12-27，261.6 MB）和 v0.2.0（2025-09-10，497.6 MB）两个版本，工具会按 Node 报告的 CPU 架构自动选择 `darwin-aarch64` 包 ([CDN 安装包 darwin-aarch64 v0.2.0](https://vela-ide.cnbj3-fusion.mi-fds.com/vela-ide/emulator/v0.2.0/darwin-aarch64.zip)；[emulator 架构选择源码](https://cdn.jsdelivr.net/npm/@aiot-toolkit/emulator@2.0.5/lib/utils/index.js))。再加上 220–414 MB 的系统镜像，首次下载约 0.7–1 GB，存放在 `~/.vela/sdk` 下 ([emulator constants.js](https://cdn.jsdelivr.net/npm/@aiot-toolkit/emulator@2.0.5/lib/emulatorutil/constants.js))。问题在于**没有手环10 专用镜像**。IDE 的设备预设里有"xiaomi10Band"，但带表盘和启动器的 miwear 5.0/4.0 镜像只支持 466×466 的手表尺寸，只有开发镜像 vela-watch-4.0 能用手环尺寸 ([IDE 多屏适配](https://iot.mi.com/vela/quickapp/zh/tools/debug/multi-screens.html))，而它没有启动器，从设备页直接运行只会显示黑屏 ([运行模拟器](https://iot.mi.com/vela/quickapp/zh/tools/emulator/emulator-run.html))。一位社区开发者在 miwear 5.0 镜像上自己建了一个 212×520、圆角 90 的模拟器，发现屏幕密度填 326 会被拒绝、填 320 才能启动，不过他是在 Linux 上测试的 ([dargon682 模拟器笔记](https://github.com/dargon682/xiaomi-band10-vela-emulator))。

模拟器的还原度也有限。官方提醒模拟器与真机存在性能差异 ([IDE 多屏适配](https://iot.mi.com/vela/quickapp/zh/tools/debug/multi-screens.html))，模拟器默认配置 4 核、1024 MB 内存 ([avdConfigIni.json](https://cdn.jsdelivr.net/npm/@aiot-toolkit/emulator@2.0.5/lib/static/avdConfigIni.json))，比手环宽裕得多；社区报告模拟器缺少大量中文字形，`scroll` 的手指滚动和右滑返回都不可靠 ([mhdbaselar](https://github.com/mhdbaselar/xiaomi-band-development))，另一位开发者的总结是"在模拟器上能正常运行，在实机上则不一定" ([cnblogs](https://www.cnblogs.com/HPC2H2/p/19504076))。官方也没有浏览器预览工具，社区项目的网页预览同样声明"不模拟 Vela 渲染" ([pickleball-band](https://github.com/mahmoodw/pickleball-band))。所以，模拟器只适合验证逻辑和大致布局，颜色、字形、触控手感和息屏行为只能在真机上确认。真机这边，零售手环上没有实时调试控制台，官方的日志拉取也要用测试版 App ([常见问题](https://iot.mi.com/vela/quickapp/zh/guide/other/faq.html))，社区的办法是把每个接口调用都包进 try/catch，把错误信息显示在屏幕上的一个 `text` 里 ([KaiTee 踩坑手册](https://github.com/KaiTeeDreamChai/xiaomi-band-dev-guide/blob/main/docs/04-pitfalls-and-solutions.md))。

**用 Claude Code 开发的话，值得装上官方的 velajs-mcp**（0.0.13，2026-07-21）。它能编译项目、启动模拟器、推送应用并热更新，还提供截图、点按、滑动和读取日志等工具，添加命令是 `claude mcp add --scope user velajs -- npx -y velajs-mcp`，前提是项目里已装 aiot-toolkit，并且至少用 AIoT IDE 创建过一个模拟器 ([npm: velajs-mcp](https://www.npmjs.com/package/velajs-mcp))；aiot-core 从 1.7.19 起还会自动往 Vela 项目里写入这份 MCP 配置 ([aiot-core 更新日志](https://vela.gallerycdn.vsassets.io/extensions/vela/aiot-core/1.7.22/1784640272242/Microsoft.VisualStudio.Services.Content.Changelog))。官方的模拟器自动化测试需要 aiot-toolkit 2.0.6-beta.17 以上的内测版 ([自动化测试](https://iot.mi.com/vela/quickapp/zh/guide/other/automated-test/))；对计分规则来说，更简单的做法是学 miSmash，把规则写成纯 JS 模块，直接用 Node 跑单元测试 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))。

**打包分调试包和发布包两种。** 调试包由 `aiot build`（IDE 里的"打包"）生成，文件名为 `dist/<包名>.debug.<版本>.rpk`，签名时依次查找 `sign/debug/` 和 `sign/` 下的证书，都没有就用工具包内置的默认证书 ([SignUtil.js](https://cdn.jsdelivr.net/npm/@aiot-toolkit/aiotpack@2.0.5/lib/compiler/javascript/vela/utils/signature/SignUtil.js))。发布包由 `aiot release`（IDE 里的"发布"）生成，必须在 `sign/` 下提供 `private.pem` 和 `certificate.pem`，可以用 `openssl req -newkey rsa:2048 -nodes -keyout private.pem -x509 -days 3650 -out certificate.pem` 生成 ([使用 AIoT-IDE 开发](https://iot.mi.com/vela/quickapp/zh/guide/start/use-ide.html))。官方要求以后的发布版一直用同一个证书 ([常见问题](https://iot.mi.com/vela/quickapp/zh/guide/other/faq.html))，所以私钥要备份，也不要提交到公开仓库。编译参数 `--enable-jsc`（把 JS 编译成字节码）默认关闭 ([编译参数](https://iot.mi.com/vela/quickapp/zh/guide/start/toolkit-params.html))，请保持关闭，有开发者报告它会让手环10 黑屏崩溃 ([QRWallet](https://github.com/mastermaiolo/QRWallet))。

## 官方装机通道对个人关闭，AstroBox 是安卓与 iPhone 用户共同的主路

### 三条官方通道都要先找小米商务

官方能把 rpk 装上真机的方式有三种，对个人开发者都不开放。**AIoT-IDE 真机调试**的页面写明"目前真机调试只支持 Xiaomi Watch S4 设备"，并且"仅对特定合作方开放"，此外还要向小米索取调试指南、刷入可调试固件、使用测试版小米运动健康，并让电脑和手机处在同一局域网 ([真机调试](https://iot.mi.com/vela/quickapp/zh/tools/devicedebug/start.html))。**小米运动健康里的第三方应用安装页**确实存在，路径是"我的 → 关于 → Debug → 第三方应用 → Install third app"，但官方 FAQ 说明带这个入口的 App "目前是通过商务拉群对接的方式提供"，第三方开发需求要发邮件到 changjian@xiaomi.com ([常见问题](https://iot.mi.com/vela/quickapp/zh/guide/other/faq.html))；正式版小米运动健康里只有一个隐藏入口，在"关于"页连点图标可以导出日志，社区用它提取 AuthKey，但它不能装应用 ([AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/))。**上架手环应用商店**要"联系工作人员 zhangyuanpu@xiaomi.com 进行合作发布" ([发布](https://iot.mi.com/vela/quickapp/zh/guide/publish/index.html))，小米 HyperOS 开发者平台还要求所有上架应用提供软件著作权证书并完成 APP 备案 ([应用资质 FAQ](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2251))。对一个自用的计分器来说，这三条路要么不支持手环10，要么需要商务关系和资质；如果以后想正式上架，上面的邮箱是唯一的官方起点，但目前找不到任何个人开发者走通的公开记录。

| minstall | Linux、Android | 从日志提取 AuthKey | 只验证过手环10 Pro | 低 |
| Gadgetbridge | Android | AuthKey，并卸载官方 App | 不能，只能装表盘和固件 | 不可用 |

**AstroBox 是社区工具里最成熟的一个。** 它由 AstralSightStudios 开发，采用 AGPL-3.0 许可但只部分开源 ([AstroBox-NG](https://github.com/AstralSightStudios/AstroBox-NG))。最新版 v2.2.0 发布于 2026-10-03，提供 Apple Silicon 与 Intel 两种 dmg、安卓 apk、Windows 和 Linux 安装包，对应的 iOS 版 2.2.2 已上架中国区 App Store，免费、含应用内购买 ([AstroBox-NG 发布页](https://github.com/AstralSightStudios/AstroBox-NG/releases)；[App Store 中国区](https://apps.apple.com/cn/app/id6785374105))。米坛知识库的支持矩阵写着"小米手环 10 系列 ✔️ 完整支持" ([AstroBox 从此开始](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-start.html))，腕管Pro 等手环10 第三方应用也把它列为第一种安装方式 ([腕管Pro 文档](https://wgpro.typheye.cn/docs/))。

连接有两种方式：登录同一个小米账号，让 AstroBox 自动导入你在小米运动健康里绑定的设备和 AuthKey，或者手动输入 AuthKey ([设备连接](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-connect.html)；[AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/))。手环不用解绑，但同一时间只能被一个应用连接，所以要先杀掉小米运动健康的后台 ([bandbbs #26473](https://www.bandbbs.cn/threads/26473/))，再在手环上进入"设置 → 我的设备（老设备为'系统操作'）→ 连接新手机"，在 AstroBox 里点选手环，然后在手环上确认，并接受系统的配对弹窗 ([设备连接](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-connect.html))。安装本地 rpk 有三种方式：在设备页的资源卡片上点"+"，在队列右上角点"+"并选择资源类型，或者在桌面版里把文件直接拖进窗口 ([资源安装](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-resource.html))。在 Mac 上，AstroBox 走经典蓝牙 RFCOMM，已知的 macOS 问题有"RFCOMM channel disconnected"（在系统里忘记设备后重新配对即可）([报错参考](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-errors.html))和启动安装队列时界面卡顿（#28，尚未关闭）([issue #28](https://github.com/AstralSightStudios/AstroBox-NG/issues/28))，装好后也可能需要执行去除隔离属性的命令 ([适用条件与安装](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-install.html))。

### 安卓用户的选择最多

如果你用安卓手机，可选的路线最多。首选仍是 AstroBox 安卓版，需要授予附近设备、蓝牙和精确位置三项权限；米坛教程还记录了一条反直觉的经验：小米手机要关掉"开发者模式"才能扫描到手环 ([AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/))。手动获取 AuthKey 的方法是在小米运动健康的"我的 → 关于"页连点图标约 10 次导出日志，再到 `Download/wearablelog` 下的压缩包里找 `encryptKey` ([AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/)；[minstall](https://github.com/uybixd/minstall))。第二选择是安卓专用的"表盘自定义工具"，它支持手环10（NFC 版需选对应的型号前缀），通过"蓝牙一键安装"装快应用，也能在"工具 → 快应用管理"里卸载，不过它的 AuthKey 读取工具需要捐赠资格，可试用 48 小时 ([表盘自定义工具](https://wiki.bandbbs.cn/Guides/watchface_custom_tool/watchface_custom_tool-install.html))。第三选择是在手机的 Chrome/Edge 里打开 BandBurg 网页，它自己拿不到 AuthKey，定位只是应急工具 ([BandBurg 教程](https://wiki.bandbbs.cn/Guides/BandBurg/bandburg-question.html))。

资料较少的路线还有几条。OronBox 的设备表同样列有手环10，可以登录小米账号或读取运动健康日志导入设备，但它支持哪些平台、是否收费都不清楚 ([OronBox 教程](https://wiki.bandbbs.cn/Guides/oronbox/oronbox-install.html))；英文社区的匹克球计分器是通过安卓应用 Notify for Xiaomi 的自定义应用安装流程装上手环10 的 ([pickleball-band](https://github.com/mahmoodw/pickleball-band))，但米坛资料没有确认过这条路线。手机已经 Root 的用户还可以用 Xposed 模块 Wearable Debug，把隐藏的"install third app"页面解锁到正式版小米运动健康里，这是唯一一条走官方 App 自身通道的路线；但这个模块只在手环8 Pro 和小米运动健康 3.44.0 上测试过，最后一次更新是 2025 年 9 月 ([Wearable-Debug](https://github.com/A5245/Wearable-Debug))，而据应用宝页面摘要，小米运动健康已更新到 3.59.1 ([应用宝](https://sj.qq.com/appdetail/com.mi.health))，两者是否兼容没人验证过。Gadgetbridge 虽然把手环10 标为"基本支持" ([Gadgetbridge 小米设备页](https://gadgetbridge.org/gadgets/wearables/xiaomi/))，但它的安装代码只处理表盘和固件，没有处理应用的分支 ([XiaomiInstallHandler](https://github.com/Freeyourgadget/Gadgetbridge/blob/master/app/src/main/java/nodomain/freeyourgadget/gadgetbridge/devices/xiaomi/XiaomiInstallHandler.java))，不能用来装 rpk。

### iPhone 用户靠 AstroBox，或借道 Mac

如果你用 iPhone，有两条主路。第一条是 AstroBox iOS 版，App Store 页面标注需要 iOS 26.1 或更高（米坛 wiki 写的是 16.5 以上，以 App Store 为准）([App Store 美国区](https://apps.apple.com/us/app/astrobox-wearable-toolkit/id6785374105)；[适用条件与安装](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-install.html))。iOS 会把蓝牙配件绑定给小米运动健康，所以每次从小米运动健康切到 AstroBox，都要先在"设置 → 蓝牙"里忽略手环，遇到 TargetRejected 错误也是同样处理 ([AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/)；[设备连接](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-connect.html))。在 iOS 上手动获取 AuthKey，要在"文件"App 的小米运动健康文件夹里打开 `MHWCahe/<数字id>/VirtualDevice_registerList/manifest.sqlite`，搜索 `encrypt_key` ([AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/))。

第二条是直接用 Mac 版 AstroBox：登录小米账号就能拿到 AuthKey，省掉在 iOS 上提取的步骤。不过手环同一时间只能连一台主机，连接 Mac 之前同样要让 iPhone 上的小米运动健康断开；这一步是根据"连接独占"规则推断的，目前没有专门的"iPhone 加 Mac"教程。其他工具对 iPhone 用户帮助不大：BandBurg 可以在 Mac 的 Chrome/Edge 里用，但不支持 iPhone，表盘自定义工具和 minstall 都没有 iOS 版 ([BandBurg 教程](https://wiki.bandbbs.cn/Guides/BandBurg/bandburg-question.html)；[minstall](https://github.com/uybixd/minstall))。对登录时被二次验证卡住的 iOS 用户，米坛知识库的建议是借一台安卓设备 ([米坛知识库](https://www.bandbbs.cn/threads/22175/))。

无论走哪条路线，还有一个悬而未决的问题：**手环到底接受调试包还是发布包。** 一份社区开发指南称必须用 `npm run build` 生成的调试包，手环固件"通常禁止未授权的自签名 Release 包" ([KaiTee 侧载指南](https://github.com/KaiTeeDreamChai/xiaomi-band-dev-guide/blob/HEAD/docs/05-sideload-and-deployment.md))，miSmash 也建议用调试包 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))；但米坛上流通的应用大多以 release 包发布（例如 `com.bandbbs.ebook.release.3.1.rpk`），用户照样通过 AstroBox 或表盘自定义工具安装 ([dargon682 模拟器笔记](https://github.com/dargon682/xiaomi-band10-vela-emulator)；[米坛知识库](https://www.bandbbs.cn/threads/22175/))。最省事的办法是先装调试包，遇到证书校验错误再换发布包。

## 风险集中在账号凭据与固件政策，不在把手环刷坏

**第一类风险是凭据，最需要认真对待。** AuthKey 是手环的连接凭据，米坛 wiki 提醒不要外传，一旦泄露就要在官方 App 里解绑再重新绑定来重置 ([设备连接](https://wiki.bandbbs.cn/Guides/astrobox/astrobox-connect.html))；反过来，解绑或恢复出厂设置会让 AuthKey 失效，硬重置还会改变蓝牙 MAC 地址 ([Gadgetbridge 配对指南](https://gadgetbridge.org/basics/pairing/huami-xiaomi-server/)；[minstall](https://github.com/uybixd/minstall))。在第三方工具里登录小米账号容易触发风控：AstroBox 的二次验证死循环问题（#4）开发者曾承诺在 2.0.0 修复，但 2026 年仍有用户报告"已触发风控"，2026 年 5 月一位手环10（非 Pro）用户在 vivo 手机上被反复要求二次验证，换了一部手机才登录成功 ([issue #4](https://github.com/AstralSightStudios/AstroBox-NG/issues/4)；[bandbbs #26473](https://www.bandbbs.cn/threads/26473/))。有教程建议干脆关掉小米账号的二次验证来绕过 ([AstroBox V2 快速上手](https://www.bandbbs.cn/threads/24538/))，这会降低整个账号的安全性；更好的选择是手动提取 AuthKey，不让第三方工具接触账号密码。BandBurg 的说明也提醒，日志里有 AuthKey、设备 ID 和账号信息，不要上传到不信任的网页 ([BandBurg 教程](https://wiki.bandbbs.cn/Guides/BandBurg/bandburg-question.html))；minstall 的免责声明则直说，这类绕过官方 App 的直连方式"可能违反厂商服务条款" ([minstall](https://github.com/uybixd/minstall))。

**第二类风险是切换连接带来的麻烦和容量限制。** AstroBox V2 在配对前总会先解除系统层面的蓝牙绑定，有用户反映每次用它连过手环之后，都得重新设置"手环解锁手机"功能 ([issue #18](https://github.com/AstralSightStudios/AstroBox-NG/issues/18))。容量方面，**除手环10 Pro 和 Xiaomi Watch S5 外，其他设备最多只能装 20 个快应用**，出现预装失败时不要继续安装 ([表盘自定义工具](https://wiki.bandbbs.cn/Guides/watchface_custom_tool/watchface_custom_tool-install.html))；在小米运动健康里下载应用时提示"系统出现错误"，往往也是因为快应用装满了。手环10 NFC 版可用空间约 323 MB，固件包约 48 MB，米坛建议至少留出固件包两倍的空间，否则下次 OTA 升级装不上 ([米坛知识库](https://www.bandbbs.cn/threads/22175/))。

**第三类风险来自小米和工具开发者的政策变化，也最难预测。** 截至 2026 年 10 月，没有发现任何手环10（非 Pro）固件阻止侧载 rpk 的报告。但同代的手环10 Pro 国际版已经出现快应用安装超时、表盘却正常的问题（#26）([issue #26](https://github.com/AstralSightStudios/AstroBox-NG/issues/26))，还有报告称其国际版固件不响应第三方应用服务 ([atc1441 issue #3](https://github.com/atc1441/MiBand10-BES2700iMP-BEST1503-Hacking/issues/3))，说明小米在固件层面完全有能力把门关上。工具这边也在收紧：AstroBox 2.2.0 已经"受小米有关部门要求"，拒绝安装疑似来自官方表盘商城的表盘 ([issue #30](https://github.com/AstralSightStudios/AstroBox-NG/issues/30))，目前只针对表盘，但说明工具的安装策略会随厂商压力变化。侧载的应用能否在 OTA 升级后保留、装第三方应用会不会影响保修，都找不到权威说法，所以要一直留着源码和 rpk 文件，以便升级后重装。

**相比之下，硬件风险很小。** 通过蓝牙安装 rpk 并不刷写固件；真正有变砖风险的是用这些工具刷写或降级固件，而计分器完全用不到这一步 ([米坛知识库](https://www.bandbbs.cn/threads/22175/))。已知最坏的情况是应用本身写得太重：前面提到的单词应用曾因内置 6000 词词库导致手环10 安装时重启 ([Bingak 单词应用](https://github.com/Bingak/MiBand10-Daily-Word-Practice))，在手环9/9 Pro 上，一个应用启动时就加载固件里没有的模块，也引发过系统重启 ([Senren-Banka](https://github.com/hrk666666/Senren-Banka-MiBand-10))。米坛给出的恢复办法是重新刷入固件或恢复出厂设置，手环10 还可以反复插拔充电，直到出现系统还原 ([米坛知识库](https://www.bandbbs.cn/threads/22175/))。反复修改、重装时还有几个小坑：`versionCode` 不变时手环会保留旧版本 ([miSmash](https://github.com/loStefa/miSmash/blob/main/README.en.md))，卸载可能清掉已保存的比赛 ([pickleball-band](https://github.com/mahmoodw/pickleball-band))，旧图标可能被缓存 ([QRWallet](https://github.com/mastermaiolo/QRWallet))。所以每次重装都要把 `versionCode` 加一，同时固定包名和签名证书不变。

## 推荐路径：先用单元测试和模拟器跑通逻辑，再用 AstroBox 上真机

下面的路径按"先定规则、再做界面、最后上真机"的顺序安排，每一步都有明确的完成标志。第 8 步的真机验收清单最关键，本报告里所有标为"未经验证"的问题，都要在那一步得出答案。

| 步骤 | 目标 | 具体操作 | 完成标志 |
|---|---|---|---|
| 1 | 理顺环境 | 让 `which npm` 指向 `~/.nvm` 下 Node 22 自带的 npm；在 VS Code 中安装 `vela.aiot-core`（会连带装上 `vela.aiot-emulator`）；如果更想用独立 IDE，就下载 AIoT-IDE 1.7.0 的 .arm 包并去除隔离属性 | VS Code 左侧边栏出现 vela 图标 |
| 2 | 建项目，改成手环10 配置 | `npm create aiot` 选 vela-demo；manifest 中把 `package` 改为 `com.<你的标识>.badminton`，`name` 用不超过 6 个汉字的短名（如"羽球计分"），设 `designWidth: 212`，`features` 声明 router、vibrator、storage、brightness、app，`deviceTypeList` 保持 `["watch"]`，`minPlatformVersion` 保持 1200，换上 192×192 图标 | `npx aiot build` 能产出 rpk |
| 3 | 先写规则引擎 | 写一个纯 JS 模块，赛制参数取（21, 20, 30, 11）或（15, 14, 21, 8），包含三局两胜、加减分和多级撤销；用 `node --test` 覆盖两种赛制的追平、封顶和比赛结束 | 单元测试全部通过 |
| 4 | 搭模拟器 | 运行 `npx aiot initEmulatorEnv`（约 0.7–1 GB）；运行 `npx aiot createVVD`（名称以 Vela 开头），或在 IDE 中用 vela-watch-4.0 镜像加 xiaomi10Band 预设，自定义尺寸时密度填 320；运行 `npx aiot start --watch`；可选添加 velajs-mcp | 能在模拟器里点动计分页 |
| 5 | 做界面 | 顶栏（局分加往里收的"更多"按钮）与红蓝色块平级；颜色写在定高容器的静态 class 上；比分用 96 px 粗体、110 px 行高；长按减分，并吞掉松手后的 click；每得一分写 storage，onInit/onShow 时恢复；onShow 开常亮、onHide 关常亮；onBackPress 拦截误触；设置页放 21/15 切换、振动开关、常亮开关、重置本局、新比赛（点两次确认）；角落显示构建号 | 在模拟器里完整打完一场三局两胜 |
| 6 | 打调试包 | 运行 `npx aiot build`，不加 `--enable-jsc`；每次装机前把 `versionCode` 加一；把 `sign/` 加入 `.gitignore` 并另外备份 | `dist/` 下出现 `.debug.` rpk |
| 7 | 连接手环 | 从 GitHub 下载 AstroBox v2.2.0 的 aarch64 dmg，必要时去除隔离属性；登录同一个小米账号，或手动输入 AuthKey；在手机上杀掉小米运动健康（iPhone 还要在蓝牙设置里忽略手环）；在手环上进入"设置 → 我的设备（或系统操作）→ 连接新手机" | AstroBox 显示手环已连接 |
| 8 | 装机并真机验收 | 把 rpk 拖进 AstroBox 窗口并开始队列；逐项检查息屏再亮屏后回到哪里、常亮是否生效、短震和长震的手感、中文和数字有没有缺字或被裁切、长按会不会误加分、右滑返回是否正常、开着原生羽毛球运动记录时能否打开、常亮一小时耗电多少 | 清单上每一项都有结论 |
| 9 | 交还连接，继续迭代 | 重新打开小米运动健康让它接管连接，手环解锁之类的功能失效时重新设置；之后改代码就重复第 6–8 步；源码、rpk 和证书各留一份，固件升级后如果应用丢了就重装 | 健康数据同步正常，计分器还在应用列表里 |

## 结论

这次调研最重要的判断是：**在手环10 上做第三方应用，难点不在技术，而在分发。** 小米把框架文档写到了逐个接口标注手环10 的程度，却只给合作方留了装机入口，于是一个个人应用能用多久，实际上取决于一个部分闭源的社区工具，以及小米对它的容忍度——AstroBox 已经应小米要求封掉了一类表盘，手环10 Pro 国际版固件也出过快应用装不上的问题。由此得出的工程策略是让应用尽量"能搬家"：保持纯本地运行，不依赖手机端联动（与手机通信还要求两边同证书签名，以及额外的同步器），源码、rpk 和签名证书各留一份。这样即使哪天 AstroBox 用不了，换到表盘自定义工具、BandBurg 或将来可能开放的官方通道时，rpk 本身一行都不用改。

第二个结论是，手环的种种限制——息屏挂起、系统右滑、只有两档振动、胶囊圆端——恰好让"全程点击、红蓝两大色块"成了最稳的交互方案，你原来的设计几乎不用妥协；真正的工程重点在状态持久化和屏幕管理，第一次上真机最该测的就是"息屏后再亮屏会发生什么"。时机也对你有利：3×15 将在 2027 年 1 月 4 日成为世界羽联主规则，而现有的手环羽毛球计分器都没写明支持 15 分制；手环11 和手环10 用的是同一块 212×520 面板 ([miband-dev 已知设备](https://github.com/sohamashodiya/miband-dev/blob/main/plugins/miband-dev/data/KNOWN_DEVICES.md))，按手环10 做好的布局大概率可以直接用到下一代。做完后发布到米坛，很可能填补一个真实的空缺。
