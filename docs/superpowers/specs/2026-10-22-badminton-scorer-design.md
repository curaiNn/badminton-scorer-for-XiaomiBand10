# 羽毛球计分（小米手环10）设计文档

- 日期：2026-10-22
- 状态：已实现（`feat/scorer` 分支），待真机验收
- 目标设备：小米手环10 NFC 版（国行，绑定小米运动健康），212×520 胶囊形 AMOLED
- 技术框架：Xiaomi Vela JS 应用（.rpk），构建工具 aiot-toolkit 2.0.5
- 背景资料：[可行性调研报告](../../../reports/小米手环10%20第三方应用开发可行性.md)

实现时的细化和出入记在[实施计划](../plans/2026-10-22-badminton-scorer.md)里，本文正文没有改：见其中「与设计文档的差异」第 1–7 条（例如 `store.js` 的读取改为返回 `{ ok, record }` / `{ ok, settings }`，用来区分读取失败和没有记录），以及 Task 8、Task 9 的执行记录。另外，5.5 的错误码新增了 `S3`：存储里的比赛记录损坏或版本不认识，已丢弃。

## 1. 目标与范围

一款装在手环上、打球时随手记分的羽毛球计分器：红、蓝代表两方，全程只用点击，不需要任何文字输入。

**要做的：**

- 点红/蓝卡片给该方加 1 分；底部「撤销」键撤回最近一分，可连续撤销
- 显示当前比分、局分、第几局，以及当前发球方和发球区（左/右）
- 三局两胜，21 分制和 15 分制可选
- 一局结束、比赛结束的提示层；决胜局到换边分数时提醒「换边」
- 本局清零、新比赛（在更多页中需二次确认；比赛结束提示层上的「新比赛」一点即生效）
- 振动反馈（可关）、比赛时屏幕常亮（可关）
- 每得一分立即存盘，退出或被系统关掉后重新打开能恢复
- 右上角「更多」进入设置页

**不做的（YAGNI）：**

- 队名、任何文字输入
- 双打具体由哪位球员发球、站位跟踪（只提示发球方和发球区）
- 局点/赛点提示、比赛计时、历史记录与统计
- 手机端联动、上架应用商店、多语言、适配手环10 以外的设备

## 2. 设备与平台约束

下列约束来自调研报告，直接决定了后面的设计：

| 约束 | 对设计的影响 |
|---|---|
| 屏幕 212×520，胶囊形，两端圆弧半径约 90–103 px | `designWidth: 212`，1 px = 1 物理像素；顶部和底部的内容要往里收，避开圆弧 |
| 事件只有 click、longpress、touch*、swipe；没有双击；除 swipe 外的事件都会冒泡 | 只用 click；顶栏、撤销键与红蓝卡片是平级元素，不嵌套，避免误加分 |
| `z-index` 无效 | 提示层用条件渲染替换卡片区域，不用层叠 |
| 振动只有 `vibrate({mode: 'short' \| 'long'})` 两档 | 用「次数 + 长短」区分事件 |
| `storage` 是异步字符串键值存储 | 存 JSON 字符串；读写都包一层 Promise |
| 应用退到后台或息屏后会停止运行，计时器挂起 | 每次状态变化立即存盘；`onShow` 时重新读取 |
| emoji 和部分符号会显示成方框 | 不用特殊符号：「更多」的三个点、发球圆点都用 CSS 画；按钮只用中文 |
| 根节点背景色在真机上显示为黑色；text 默认颜色接近黑色 | 颜色写在定高的内层容器上；每段文字都显式写颜色 |
| `border-radius` 必须同时设置 border-width 和 border-color 才生效 | 圆角元素都带同色边框 |
| `showToast` 只能显示在屏幕正中，会挡住比分 | 不用 toast，提示放在顶栏 |
| manifest 的 `name` 限 6 个汉字 | 桌面名用「羽毛球计分」 |

## 3. 界面

视觉风格：**深色卡片**。纯黑底，红蓝两方各一张深色卡片，比分数字用该方的亮色。暗底亮像素少，整场常亮更省电。

### 3.1 计分页

纵向布局（单位为设计像素，屏幕 212×520；数值为起点，以模拟器和真机效果微调）：

```
 y=0   ╭───────────────────────╮  胶囊顶端圆弧
 18    │ 第2局 · 21分      (⋯) │  顶栏，高 64
       │ 1 : 0                 │   左：第几局·赛制 / 局分；右：「更多」按钮
 82    │┌─────────────────────┐│
       ││ ● 右区发球          ││  红卡片，高约 177
       ││         12          ││   发球提示（仅发球方显示）+ 比分
       │└─────────────────────┘│
       │         间隔 8         │
       │┌─────────────────────┐│
       ││         10          ││  蓝卡片，高约 177
       │└─────────────────────┘│
       │         间隔 10        │
       │       ( 撤销 )        │  撤销键 112×44
 498   │                       │
 520   ╰───────────────────────╯  胶囊底端圆弧
```

- **卡片**：左右各留 12，圆角 20。整张卡片都是点击区域，点一下该方 +1。按下时卡片底色变亮（切换 class），松手或 click 时恢复（真机 touchend 偶尔丢失，click 里也要恢复）。
- **比分数字**：96 px 粗体，行高 110 px（行高低于字号约 1.33 倍会裁切数字）。
- **发球提示**：在发球方卡片的比分上方显示「● 右区发球」或「● 左区发球」，圆点用 8×8 的圆形 div。整场比赛第一球之前不显示。
- **顶栏**：内容左起不小于 44、按钮右缘不超过 170（避开圆弧）。第一行「第 2 局 · 21分」14 px 灰字，赛制显示的是本场比赛的赛制（可能与设置不同，见 4.3）；第二行局分「1 : 0」20 px，红蓝数字分别用两方颜色。「更多」按钮 40×40 圆形，内含三个 5×5 圆点。
- **撤销键**：112×44 胶囊按钮。没有可撤销的分时文字变暗，点击无反应。
- **顶栏提示**：顶栏左侧临时替换为一行提示文字，到时恢复：
  - 「换边」（琥珀色，3 秒）：决胜局一方先到 11 分（15 分制为 8 分）时
  - 「再滑一次退出」（2 秒）：第一次右滑返回时

### 3.2 局结束 / 比赛结束提示层

一局结束时，红蓝两张卡片所在区域整体替换为提示层（防止误触进入下一局），顶栏和撤销键保留：

- **一局结束**：「红方胜第 1 局」（该方颜色，18 px）、本局比分「21 : 18」（48 px 粗体）、小字「交换场地后开始下一局」、主按钮「下一局」（140×48）。
- **比赛结束**（一方先胜两局）：「红方获胜」、局分「2 : 1」、每局比分「21:18  19:21  21:15」（13 px 灰字）、主按钮「新比赛」。
- 提示层显示时，「撤销」仍可用：撤回结束这一局（或这场）的那一分，回到比赛中。
- 「新比赛」在这里一次点击即生效，不需要二次确认（比赛已经结束，不会丢失进行中的比分）。

### 3.3 更多页

从上到下：

1. 标题「更多」
2. **计分规则**：两个并排按钮「21 分」「15 分」，选中项浅色底（表示设置中的赛制）。设置的赛制与本场比赛不同时（比赛进行中切换过），下方显示小字「新比赛生效」
3. **振动反馈**：开关（整行可点）
4. **屏幕常亮**：开关（整行可点）
5. **本局清零**：第一次点击变成「再点一次确认」（暗红底），3 秒内再点才执行，否则恢复原样；执行后自动回到计分页
6. **新比赛**：同上
7. **返回计分**：回到计分页（系统右滑也能返回）
8. 版本号「v1.0.0」，出错时后面追加错误码（见 5.5）

开关用自绘的 div，不用系统 switch 组件，以便控制样式。整页高度在 520 以内，不需要滚动。

## 4. 计分逻辑

### 4.1 赛制

三局两胜。两种赛制用同一套规则，只有参数不同：

| 参数 | 21 分制 | 15 分制 |
|---|---|---|
| 每局目标分 `target` | 21 | 15 |
| 封顶分 `cap`（先到即胜） | 30 | 21 |
| 决胜局换边分 `swapAt` | 11 | 8 |

一局的胜负：一方得分 ≥ `target` 且领先 ≥ 2 分，或者一方先到 `cap`。由此自然得到「20 平（15 分制为 14 平）后须领先 2 分」。

### 4.2 比赛记录

比赛只记录**每一分由谁赢得的顺序**，其余一切由这串记录推算：

```
{ v: 1, rule: 21, pts: "RBRRB…", acked: 1 }
```

- `rule`：本场比赛的赛制（21 或 15），开赛时从设置里取，比赛中不变
- `pts`：得分序列，`R` 为红方得分，`B` 为蓝方得分；整场最多约 180 个字符
- `acked`：用户已点过「下一局」的已结束局数

推算方式：按顺序回放 `pts`，一局分出胜负后，后续得分记入下一局。得到：

- 每局比分与胜方、已结束局数 `completed`、局分
- 阶段 `phase`：
  - `matchOver`：一方已胜两局
  - `gameOver`：`completed > acked`（刚结束一局，等用户点「下一局」）
  - `playing`：其余情况
- 当前显示的局：`playing` 时为第 `acked + 1` 局（可能是 0:0）；`gameOver` / `matchOver` 时为刚结束的那一局
- 发球方与发球区（见 4.4）

### 4.3 操作

| 操作 | 规则 |
|---|---|
| 得分 | 仅在 `playing` 时有效：`pts` 末尾追加 `R` 或 `B` |
| 撤销 | 删除 `pts` 最后一个字符，然后令 `acked = min(acked, completed)`。效果：撤回结束一局的那一分，提示层消失、回到该局比赛中；在新一局 0:0 时撤销，会回到上一局结束前的状态；比赛结束后同样可撤回；`pts` 为空时无效 |
| 下一局 | 仅在 `gameOver` 时有效：`acked = completed` |
| 本局清零 | 只保留前 `acked` 局的得分，删除之后的全部得分。进行中的局回到 0:0；提示层显示时，刚结束的那一局回到 0:0。不可撤销（靠二次确认防误触） |
| 新比赛 | `{ v: 1, rule: 设置中的赛制, pts: "", acked: 0 }` |
| 切换赛制 | 保存到设置。若当前比赛还没开始（`pts` 为空），同时修改本场的 `rule`；否则本场不变，下一场新比赛生效 |

### 4.4 发球

- 发球方：当前局中上一分的得分方。当前局还没有得分时：第 1 局不显示；第 2、3 局由上一局胜方发球
- 发球区：发球方当前得分为双数（含 0）时在右区，单数在左区
- 双打只提示哪一方、哪个区发球，具体由谁发由球员自己判断

### 4.5 振动

振动反馈关闭时全部不震。

| 事件 | 振动 |
|---|---|
| 得分、撤销 | 短震 1 次 |
| 一局结束 | 长震 1 次 |
| 比赛结束 | 长震 2 次 |
| 决胜局换边（一方得分首次到达 `swapAt`） | 短震 2 次 |

两次振动之间的间隔初定 300 ms（短震）和 800 ms（长震），上真机后按手感调整。

## 5. 技术实现

### 5.1 结构

两个页面，用 `@system.router` 跳转。另一种做法是把设置做成计分页里的浮层，少一次页面切换，但计分页会更重；两页结构与「进入设置页面」的需求一致，计分页也更简单。

```
package.json             aiot-toolkit 2.0.5；脚本 start / build / release / test
src/
  manifest.json
  app.ux
  common/
    rules.js             纯函数：赛制参数、单局胜负、由比赛记录推算完整状态
    match.js             纯函数：得分 / 撤销 / 下一局 / 本局清零 / 新比赛 / 切换赛制 / 校验
    store.js             读写比赛记录与设置（封装 @system.storage）
    device.js            振动模式、屏幕常亮（封装 @system.vibrator、@system.brightness）
  pages/
    score/score.ux       计分页（含两种提示层）
    more/more.ux         更多页
  images/icon.png        192×192 图标
test/
  rules.test.js
  match.test.js          用 Node 自带的 node --test，不引入测试依赖
```

### 5.2 模块接口

**rules.js**（不依赖任何系统接口，可在 Node 里直接测试）

```js
RULES = { 21: { target: 21, cap: 30, swapAt: 11 }, 15: { target: 15, cap: 21, swapAt: 8 } }
isGameWon(own, other, rule) -> boolean
deriveMatch(record) -> {
  phase,            // 'playing' | 'gameOver' | 'matchOver'
  games,            // [{ red, blue, winner }]，已开始或已结束的局
  completed,        // 已结束局数
  gamesWon,         // { red, blue }
  current,          // { index, red, blue }，当前显示的局
  server,           // 'R' | 'B' | null
  court,            // 'right' | 'left' | null
  matchWinner,      // 'R' | 'B' | null
}
```

**match.js**（纯函数，输入旧记录、返回新记录，不修改入参）

```js
newMatch(rule) -> record
addPoint(record, side) -> { record, event }   // event: 'point' | 'game' | 'match' | 'swapEnds' | null
undo(record) -> record
nextGame(record) -> record
resetGame(record) -> record
setRule(record, rule) -> record
normalize(raw) -> record | null                // 校验从存储读出的数据
```

`addPoint` 的 `event` 由得分前后的推算结果比较得出：比赛结束优先，其次一局结束，再次决胜局换边，其余为普通得分；非 `playing` 阶段返回原记录和 `null`。

**store.js**

```js
loadMatch() -> Promise<record | null>
saveMatch(record) -> Promise<boolean>
loadSettings() -> Promise<settings>          // 失败时返回默认设置
saveSettings(settings) -> Promise<boolean>
lastError() -> string                         // 没有错误时为空串
```

**device.js**

```js
buzz(event, enabled)   // 按 4.5 的模式振动；enabled 为 false 时什么都不做
keepScreenOn(on)       // 调用 brightness.setKeepScreenOn
```

### 5.3 页面流程

**计分页**

- `onInit`：读设置和比赛记录（没有记录就新建），完成前忽略点击
- `onShow`：重新读取（更多页可能改过），按设置开启常亮
- `onHide` / `onDestroy`：关闭常亮
- 点卡片：`addPoint` → `deriveMatch` → 刷新界面 → `saveMatch` → `buzz(event)`
- 撤销 / 下一局 / 新比赛：同样走「改记录 → 推算 → 刷新 → 存盘 → 振动」
- `onBackPress`：第一次返回 `true` 并显示「再滑一次退出」，2 秒内第二次则放行，交给系统退出

**更多页**：每个操作都通过 store.js 写入；本局清零、新比赛执行后 `router.back()` 回到计分页，由计分页的 `onShow` 读取新记录。

### 5.4 存储格式

| 键 | 值（JSON 字符串） | 默认值 |
|---|---|---|
| `bs.match` | `{"v":1,"rule":21,"pts":"","acked":0}` | 新比赛 |
| `bs.settings` | `{"v":1,"rule":21,"vibrate":true,"keepOn":true}` | 21 分制、振动开、常亮开 |

`normalize` 拒绝以下数据：版本号不是 1、赛制不是 21/15、`pts` 含 R/B 以外的字符或超过 200 个字符、比赛结束后还有得分、`acked` 不在 0 到 `completed` 之间。被拒绝时按「没有记录」处理，开一场新比赛。

### 5.5 出错处理

- 读取失败、数据损坏或版本不认识：开新比赛、用默认设置，不崩溃
- 写入失败：继续用内存里的状态，下次写入成功即补上
- 振动、常亮接口失败：忽略，不影响计分
- 所有系统接口调用都包在 try/catch 和 fail 回调里。零售手环没有调试控制台，所以最近一次错误记为短代码，显示在更多页版本号后面：
  - `S1`：读取失败
  - `S2`：写入失败
  - `V`：振动失败
  - `K`：常亮失败

### 5.6 manifest 要点

- `package`：`com.curain.badminton`
- `name`：`羽毛球计分`
- `versionName`：`1.0.0`
- `versionCode`：`1`，每次装机前加 1
- `minPlatformVersion`：`1200`，若装不上再试 1000
- `deviceTypeList`：`["watch"]`（填 band 会装机失败）
- `config.designWidth`：`212`
- `features`：`system.router`、`system.storage`、`system.vibrator`、`system.brightness`、`system.app`（凡是 import 的模块都要声明，漏声明会编译失败）
- `router`：入口 `pages/score`，另有 `pages/more`
- 构建：不加 `--enable-jsc`（有报告称会导致手环10 黑屏）

## 6. 测试与验收

### 6.1 单元测试（`node --test`）

- **单局胜负**：21:19 胜、21:20 未胜、22:20 胜、30:29 胜（封顶）；15 分制 15:13 胜、15:14 未胜、16:14 胜、21:20 胜（封顶）
- **三局两胜**：2:0 结束、1:1 进入第 3 局、2:1 结束
- **发球**：
  - 第 1 局开局不显示
  - 得分方发球，按得分单双判断左右区
  - 第 2、3 局开局由上一局胜方在右区发球
- **换边事件**：
  - 只在第 3 局、首次到达 `swapAt` 时触发
  - 前两局不触发
  - 两种赛制各测一次
- **阶段**：`gameOver` / `matchOver` 时得分无效；下一局后回到 `playing`
- **撤销**：
  - 普通撤销
  - 撤回结束一局的那一分
  - 在新局 0:0 时撤销回到上一局
  - 撤回结束比赛的那一分
  - 空记录撤销无效
- **本局清零**：在进行中、`gameOver`、`matchOver` 三种阶段各测一次
- **切换赛制**：未开赛时立即生效；开赛后只影响新比赛
- **数据校验**：`normalize` 能拒绝 5.4 列出的各类坏数据

### 6.2 模拟器检查

在 212×520 的自定义模拟器上（密度填 320），用两种赛制各打完一场三局两胜：

- 布局和圆弧避让
- 提示层
- 更多页各项操作
- 撤销跨局

右滑返回在模拟器上不可靠，留到真机验证。
